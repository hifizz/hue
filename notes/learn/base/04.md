> tools 与 toolChoice、activeTools

tools 注册了工具，如果 activeTools 指定了几个工具，那么未指定的工具，模型将看不到对吗？

toolChoice 指定了工具，就是模型要强制执行对不
---

先核对源码里这两点，我之前只读了 `filterActiveTools`，没确认过滤后的集合是否就是发给模型的那一份。

## 1. `activeTools`：未列出的工具，模型看不到

对。我读了 [stream-text.ts](../thread-chatbot/fix-compact-issue/node_modules/ai/src/generate-text/stream-text.ts) 第 2022 到 2056 行，每一步的顺序是：

1. `filterActiveTools({ tools, activeTools })` 先把工具集过滤成子集
2. `prepareTools(...)` 把这个子集转成发给 provider 的工具定义
3. 请求里只带这个子集

所以没列出的工具不会出现在这一步的请求里，模型不知道它们存在，也就不会去调。`activeTools` 只在你传了数组时才过滤，不传（`undefined`）则全部可见。

它和直接少传 `tools` 的区别是：`tools` 仍然是完整定义，所以历史消息里出现过的工具调用和结果，类型和转换都不受影响。你的 `convertToModelMessages(resolvedMessages, { tools: allTools })` 用的就是完整集合，这点是对的。

## 2. `toolChoice` 指定工具：强制的是"模型输出一个 tool call"，不是"工具被执行"

分两层：

- **模型层**：Anthropic 文档说，`tool_choice` 为 `any` 或 `tool` 时，API 会预填 assistant 消息来强制调用。所以这一步模型的输出一定以这个工具的 `tool_use` 开头。
- **执行层**：工具照常由 SDK 的 `execute` 执行，和 `auto` 时没有区别。

强制调用有三个副作用，都是文档写明的：

- **模型不会先说一句话。** 文档原话：*"the models will not emit a natural language response or explanation before `tool_use` content blocks, even if explicitly asked to do so."*
- **这一步会跳过 thinking。** 响应直接从 `tool_use` 开始，没有 `thinking` 块。
- **改 `toolChoice` 会让 prompt cache 里的消息块失效。** 文档说工具定义和 system 仍然命中缓存，消息内容要重新处理。

它只管这一步。你的 `createToolStepPolicy` 只在 `stepNumber === 0` 强制，第 1 步起回到 `auto`，所以模型拿到搜索结果后可以自由决定下一步。

## 一个需要你核实的风险

文档里有一张表：**Claude Opus 5.5、Sonnet 5.5、Fable 5.1、Mythos 5.1 不支持强制调用，`any` 和 `tool` 会直接返回 400 错误。** 手动开启 `thinking: {type: "enabled"}` 时也不支持。文档给的替代方案是 `auto` 加 strict tool use。

你的 [token-router.ts](../thread-chatbot/fix-compact-issue/constants/models/token-router.ts) 里有 `claude-fable-5-1`、`claude-opus-5-5`、`claude-sonnet-5-5`。如果用户选这几个模型、又触发了 `forceWebFirst`，`prepareStep` 会返回 `toolChoice: { type: "tool", ... }`，请求可能被拒。

我没有验证的部分：你的请求是经过 token-router 转发的，它是原样透传还是自己做了转换，我没看，所以不确定实际会不会报 400。你可以用 `claude-opus-5-5` 加一句明确要求联网的问题实际试一次，看第 0 步有没有报错。如果会报，修法是对这几个模型不返回强制 `toolChoice`，改成在 system 里写一句"先联网检索"。

另外，OpenAI 兼容模型（deepseek、qwen 等）对强制 `toolChoice` 的支持情况，我这次也没查。
