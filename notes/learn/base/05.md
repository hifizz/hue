> prepareStep

模型能否在输出中指导下一次该怎么调整这个 prepareStep 的输出的 配置？

---

我先确认一下 v7 里工具和 `prepareStep` 之间能传什么数据，免得凭印象回答。

可以，但**模型不能直接指挥 `prepareStep`**。中间必须有一段你写的代码把模型的输出翻译成配置。

## 为什么不能直接指挥

`prepareStep` 是你的代码，在每个 step 发请求之前由 SDK 同步调用（`stream-text.ts` 第 2003 行）。它的返回值（`model`、`toolChoice`、`activeTools`、`maxOutputTokens`、`reasoning` 等）是请求参数。模型看不到这些参数，只会产出 token。

所以模型的"意愿"只有一条路能影响下一步配置：**先变成你代码能读到的数据，再由你的 `prepareStep` 决定要不要采纳**。

## 三种可行做法

**1. 通过工具调用传信号（最常用，也最可靠）**

给模型一个"自我调整"的工具，比如 `request_deeper_analysis`。模型调用它，工具的参数（结构化 JSON）就是信号。`prepareStep` 里读上一步的 `steps`：

```ts
prepareStep: ({ steps }) => {
  const last = steps.at(-1)
  const asked = last?.toolCalls.some(c => c.toolName === 'request_deeper_analysis')
  return asked ? { reasoning: 'high', maxOutputTokens: 32_000 } : undefined
}
```

`PrepareStepFunction` 的参数里确实有 `steps`（已完成的步骤）、`messages`、`responseMessages`，类型定义在 `dist/index.d.ts` 第 1641 行附近。工具调用是结构化的，不用从自然语言里解析，这是关键优势。

**2. 通过 `runtimeContext` 传状态**

文档（`17-runtime-and-tool-context.mdx`）说 `prepareStep` 可以返回新的 `runtimeContext`，对当前步和之后所有步生效。适合记录"已经搜了几次""预算用了多少"这类跨步状态。工具的 `execute` 里不能改它（文档要求 tool context 视为不可变），要改只能在 `prepareStep` 里根据上一步结果改。

**3. 解析模型的文本输出**

比如模型写"我需要更多思考"，你用正则去匹配。**不推荐。** Anthropic 文档里有一句直接相关的话：*"if you're writing a regex to extract a decision from model output, that decision should have been a tool call."*

## 有一个要注意的限制

配置是**下一步**才生效，不能改当前正在生成的这一步。而且有些东西改了代价很大：

- 改 `activeTools` 或 `instructions` 会改变发给模型的前缀，可能让 prompt cache 失效。这也是你 `tool-step-policy.ts` 注释里说"工具面在轮内恒定"的原因。
- 在一个 thinking 开着的工具循环里，Anthropic 要求把上一步的 thinking 块原样传回。`prepareStep` 里如果改了 `messages`，要小心别丢掉或改动这些块。

## 你的代码里已经有一半

`createToolStepPolicy` 读的是 `stepNumber`（一个客观计数），所以它是"代码决定"，不是"模型决定"。要让模型参与，就是上面第 1 种：加一个信号工具，在 policy 里读 `steps.at(-1).toolCalls`。

不过这个设计有个取舍要想清楚：让模型能给自己加 `reasoning` 和 `maxOutputTokens`，等于把成本控制权部分交给了模型。一般的做法是模型只能在你设定的**范围内**选（比如只能在 `medium` 到 `high` 之间切），上限仍由你的代码卡住。
