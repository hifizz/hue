# 任务：@hue/ai —— 把模型统一成 ModelPort

**预算** 900 行 · **依赖** core · **合同** `modelPortContract`、`checkChunkStream`

## 目标
实现 `ModelPort`（见 `core/src/model.ts`），先支持 Anthropic 和 OpenAI 两家，并能用同一个配方无改动切换。

## 对外 API
```ts
import { model } from '@hue/ai'
const m = model('anthropic:claude-sonnet-4-5', { apiKey?, baseURL?, maxRetries?: 2 })
const o = model('openai:gpt-5', {...})
```
- `model(id)` 按前缀分发到 provider；未知前缀直接抛错。
- `apiKey` 默认读环境变量 `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`。

## 必须做到
1. **消息转换**：Hue `Message[]` ↔ 各家格式，双向。`instructions` 映射到各家的 system 位置。
2. **流式拼装**：把 provider 的碎片拼成 core 的 `ModelChunk`：
   - `tool-call` 只在参数完整后发一次，`input` 是解析好的 JSON；JSON 解析失败时 `input = { __raw: 原文 }`（loop 会把错误回给模型）
   - `tool-input-delta` 可选（给 UI）
   - 推理块结束时发 `reasoning-end`，带上 provider 的签名 / 加密内容到 `providerMetadata`（key 用 provider 名）
   - `finish` 恰好一次，且是最后一块
3. **providerMetadata 往返**：上一轮 assistant 消息里的推理签名必须原样送回同一 provider，否则对方会拒绝。换了 provider 时丢掉别家的 metadata。
4. **错误映射**：超出上下文窗口 → `{ code: 'context_overflow' }`（loop 靠这个触发压缩重试）；限流 / 5xx → 先按 `maxRetries` 指数退避重试，放弃后 `model_error, retryable: true`；鉴权失败 → `model_error, retryable: false`。
5. **用量**：`Usage` 填齐，包括 cache 读 / 写和推理 token。
6. **abort**：signal 触发时立刻中断 HTTP 流并抛 `AbortError`。
7. `info`：每个已知模型的 contextWindow、supports；未知模型给保守默认值并在 README 说明。

## 你来决定（写进 DECISIONS.md）
- **直接用 fetch 手写，还是封装 AI SDK 的 provider 包？** 我的建议：手写 fetch + SSE 解析，两家各约 300 行。理由：面试会问"你怎么处理 tool call 流式拼装和推理签名"，手写才讲得清；也保持零依赖。若选封装，需说明如何保证 providerMetadata 往返。
- **prompt cache 断点**放在哪（Anthropic 的 cache_control）：建议 instructions 末尾 + 工具列表末尾 + 倒数第二条用户消息。
- `countTokens` 是否实现（Anthropic 有官方计数端点）。

## 额外测试
- 用录制的 SSE fixture（`test/fixtures/*.sse`）做离线测试：纯文本、并行两个 tool call、带推理签名、参数 JSON 被截断、中途 5xx 后重试成功、超窗错误。每个都要过 `checkChunkStream`。
- 消息转换的往返测试：Hue → provider → 喂回，结构不丢。
- 真实调用的 `modelPortContract` 在有 key 时跑，没有就 skip。

## 不做
不做 prompt 拼装、不做工具执行、不做 token 估算之外的上下文管理。
