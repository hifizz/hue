# 13 个 harness「运行记录」调研：谁的事件日志是真相

调研日期：2026-11-16。问题：每个项目怎么记录"agent 运行中发生的事"（模型响应、工具调用、审批、错误、状态变化）。
本文只答三问：①有没有事件类型定义；②谁消费；③落不落盘、崩溃能否续跑。外加一列主观归类。
写作原则：描述取舍，不评好坏；没核实到的写「未核实」。

## 3. 归类详述

索引：C = fx、openhands-sdk、kimi-code、dim、grok-build、codex｜B = ai、goose、ZCode｜D = mastra、minimax-code、pi｜投影端 = OpenHands Canvas｜纯 A = 无。

### C：事件日志即真相

**fx**。账是 `~/.fx/sessions/v2/<id>/log.jsonl`：11 种 `Kind` 行、CRC32C 帧、行级 seq。判定的关键不在"有个日志文件"，而在三件事全部落在日志语义内：①状态唯一由 fold 推出——`snapshot` 行被注释明确定性为 "a cache"（`fold.zig:222-224`），且有 TLA+ 模型证明"最新快照+尾部"等价于全量 fold（`fold.zig:7`）；②崩溃修复不改写历史、而是把 `turn_interrupted{crash}`、`child_finished{interrupted|lost}` **追加成新事件**（`session.zig:1400-1447`）；③连 fsync 都按语义边界调度（`needsSync`，`session.zig:1105-1120`）。边界：wasm js_host 路径是整快照/commit 的宿主适配，v1 旧布局只读自动转 v2——都不构成第二个真相。

**openhands-sdk**。账是每 conversation 目录下的 `event-{idx:05d}-{id}.json` 一事件一文件 + `base_state.json` 游标。判据：事件由 `parent_id` 组织成**树**（支持 fork/分支）；`View` 是 fold 出的只读投影；`_default_callback` 把落盘刻意排在订阅链第一位（注释原文 "no subscriber is told about an event that is not on disk yet"，`local_conversation.py:474-481`）；恢复=重放+`get_unmatched_actions` 找悬挂 action 补跑；官方 benchmark 自称 "Event-Sourced State"。边界：`base_state.json` 存配置和 leaf 游标，是导航辅助不是第二真相；`StreamingDeltaEvent` 是显式 transient 例外。

**kimi-code**。账是每 agent 一份 `wire.jsonl`，`Event2` 子类各带 `durable`/`observable` 旗标。判据：`cls.durable` → `wire.appendRecord(serialize())`（`eventDispatcherService.ts:676-680`），restore 走 `replayRecords()` 重折（`:780,838`）；断尾有修复。边界：UI 看到的 transcript ops 是 `observable` 流的投影产品，不是账本体；delta 类事件只 observable 不落盘——durable/transient 是**类型级声明**，本表最显式的一家。

**dim**。账是 sqlite `timeline_events` 表（body=事件 JSON，`codec.rs:389-445`）。判据：落的是事件本体而非投影；恢复=`restore_session`→Dispatcher 从 `restored_sequence` 重放（`dispatcher.rs:280`）；checkpoint 只是加速件。边界：对外冻结契约 `v1::EventKind` 是契约面，与内部账两层。

**grok-build**。账是 `updates.jsonl`，注释自称 "the durable source of truth … restores from its update stream alone"（`storage/mod.rs:254-255`）。判据：按 eventId 游标重放恢复（`replay.rs:240-352`）；`chat_history.jsonl` 是**可重建派生缓存**、`events.jsonl` 是纯遥测——三轨分工，权威轨明确。边界：transient 通知不落盘（`updates.rs:465-506`）。

**codex**（混合账）。账是 `rollout-*.jsonl` 的 `RolloutItem` 联合。判据：resume/fork 走 `reconstruct_history_from_rollout`（`rollout_reconstruction.rs:191`）。为什么是"混合"：账里同时装 `ResponseItem`（模型上下文材料，全落）和按策略过滤后的 `EventMsg`（多数标 "Transient, non-durable" 不落，`policy.rs:128-187`）——账本成立，但只有一部分运行期事件有资格进账。

### B：有事件类型，持久真相是消息/转录

**ai**。账：无——核心 SDK 完全不落盘，持久化通过 `onEnd` 等回调外包给用户代码（`stream-text-result.ts:54-77`）。判据：`UIMessageChunk`/`TextStreamPart` 是流式传输契约，消费者全是 UI 链路（processUIMessageStream→Chat→useChat/SSE）。边界：`packages/harness` 的 per-turn `event-log.ndjson` 是 best-effort 崩溃镜像、注释自称 in-memory 才是真相——局部 C 小岛，不改主结论。

**goose**。账是 sqlite `messages` 表。判据：`AgentEvent` 仅 5 variant 且只活在内存流（注释级 UI 用途）；tool call、审批、错误都编码在 `Message.content` 里；`--resume` 载回消息并**从消息内容重建**挂起审批（`tool_confirmation.rs:100-141`）——事件是消息的伴生通知，不是真相。

**ZCode**。账是 sqlite `message/part/session_entry` 等投影表。判据：`SessionEventStorePort` 全仓唯一实现是 `InMemorySessionEventStore`（按 turn 窗口淘汰）；恢复方向是 transcript→事件——`loadPersistedEvents` 从持久化的 message/part **反合成**事件补 ephemeral 状态（`v4-bridge.ts:1993-2037`）。这是和 C 类正好相反的重建方向。边界：`dwf_event` 表是真事件日志小岛；远端 `web-remote-replayable` 服务的持久化未核实。

### D：分裂——同一仓给出不同答案

**mastra**（按功能域分账）。问 agent：B——`ChunkType` 流只喂 UI/pub-sub/TTL 缓存，持久真相是 `MastraDBMessage` 消息行。问 workflow：近 C——v1 周期整快照，v2 @experimental append-only `WorkflowRunEntry` journal 可按 seq materialize 重建 run，`restartAllActiveWorkflowRuns` 崩溃重驱动。两个子系统各自回答三个问题，答案不一致，故 D。

**minimax-code**（代际分裂，方向 C→B）。v1 `local-runtime`：每 session `ledger.jsonl` 事件账，注释 "the ledger is the source of truth"，快照+重放恢复（C）。v2 `local-runtime-v2`（TUI 实走）：事件只进内存 ring，真相是 canonical `messages.jsonl`+sqlite display 行，崩溃靠 `repairCanonicalHistory` 修消息历史（B）。且这是**主动的方向性撤退**——从事件账退回消息日志+修复器，值得单独记录。

**pi**（按包分裂，两套持久化哲学）。`coding-agent`：运行时 `AgentEvent`/`AgentSessionEvent` 是易失 UI/RPC/扩展流（B 面），但持久真相不是消息表而是 append-only `SessionEntry` 记录账——11 种语义记录（含 usage/compaction/model_change/label/context_edit）、id/parentId 树、撕裂尾行修复、投影重建（近 C 的记录日志）；代价是只在 `message_end` 落盘、中途崩溃丢当前 turn。`durable`：提交制记录存储——entries 不可变 + task/submission 覆盖式状态机行 + 文档 base+delta，原子 commit 批；恢复=`TaskScheduler.open` 扫状态机+checkpoint 续跑，不是事件重放。两包不共享类型/存储（coding-agent 不依赖 durable），故 D。

### 投影端：本身不拥有账

**OpenHands Canvas**。它不是 A/B/C 的任何一种，因为"账"根本不在本仓：16 种 `OpenHandsEvent` 是对 agent-server 类型的本地镜像，持久真相在远端（`DurableFrame.seq` = "its log index"）；本仓只做内存 zustand 投影 + REST 拉页 + WS `after_seq` 重放。它所属的 Canvas+agent-server 系统整体是 C，本仓是那套 C 的客户端切面。

### 共性观察

- **C 类普遍区分 durable/transient**：kimi 用 `durable`/`observable` 旗标、codex 按策略表过滤、openhands `StreamingDeltaEvent` 不落盘、grok transient 通知不落——共同模式是"逐 token 增量只喂 live 通道，账本只记完整语义事件"。
- **崩溃修复本身被记成事件**：fx 的 `turn_interrupted{crash}`/`child_finished`、kimi 的断尾修复记录——修复不是改账，而是向账里追加新事实。
- **纯 A 无**：最轻的项目（goose、AI SDK）也都定义了明确的流式事件 union；"没有事件词汇"这个项目里不存在。
