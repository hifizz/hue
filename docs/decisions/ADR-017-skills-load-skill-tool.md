# ADR-017 skills 用专门的 `load_skill` 工具加载，不让模型直接 read 文件
- 状态：已接受（2026-11-12 回填，2026-11-12 经用户阅读确认）
- 包：@hue/skills
- 来源标记：无 `DECIDE:`。出处 skills DECISIONS 第 1–3 条

## 问题
技能（SKILL.md）的正文怎么给到模型？技能目录里的脚本谁执行？

## 候选
1. 提示里只放索引，模型用 `read` 读文件。
2. 提示里放索引，加一个由宿主执行的 `load_skill` 工具。

## 各家怎么做（附出处）
Claude Code 是让模型直接读文件还是用专门工具，没对照过源码 `TODO(verify)`。Anthropic Agent Skills 的目录布局和 frontmatter 规范也没有核实过细节 `TODO(verify)`。

## 决定
选 2。技能目录在宿主上，而 agent 的 `read` / `bash` 在沙箱里（Docker 只挂载仓库），模型看不到技能目录的路径。工具由宿主进程执行，不依赖沙箱里有什么；工具名也让回放里一眼看出哪次用了技能。
- 兼容 Anthropic 的目录布局和 `name` / `description`，其余字段忽略；名字规则从严，不合法的跳过并记入 `problems`。
- `load_skill` 能读技能目录里的文本文件，但**不执行任何东西**。脚本要用，模型读出来再用 `bash` 在沙箱里跑，经过 policy 和沙箱。
- 读文件边界：用 realpath 比较；`../`、绝对路径、指向目录外的符号链接、同前缀的兄弟目录都拒绝；大小上限 100KB，二进制拒绝。
- 每个 turn 开始时扫描，加技能不用重启。

## 代价
多一个工具说明占 token（只有存在技能时才加）。技能带的脚本在沙箱里没有现成文件，模型要先写进去再跑。**下载来的第三方技能等于第三方给模型的指令，目前没有审核或签名。** `load_skill` 是宿主上的读文件，沙箱挡不住它，所以只能读技能目录。

## 何时要改
沙箱总是能看到技能目录时（local 模式，或把目录挂进容器），直接 `read` 更简单。

## 如何验证（eval / 测试）
- 路径越界测试（`../`、绝对路径、符号链接、`pdf` 与 `pdf-private`）。
- 没用真实模型、没用官方技能实测过；没有"需要 skill 才能完成"的 eval 题。
