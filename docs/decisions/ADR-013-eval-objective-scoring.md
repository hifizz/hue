# ADR-013 eval 只用客观判分：一条命令的退出码，判分前重写测试文件
- 状态：已接受（2026-11-12 回填，2026-11-12 经用户阅读确认）
- 包：@hue/eval
- 来源标记：`DECIDE: 评分方式——测试通过（客观）为主，LLM judge 为辅？`（docs/packages/eval.md:19）。同页 `DECIDE: 对照组`（eval.md:17）**仍未决**，见 docs/decisions/README.md

## 问题
怎么给一次 agent 运行打分？agent 能不能靠改测试作弊？判分在哪里跑？

## 候选
1. 测试通过为主，LLM judge 为辅。
2. 只做客观判分：一条命令，退出码 0 算通过。

## 各家怎么做（附出处）
没有核实过。

## 决定
选 2。judge 本身要被评测，多一层不确定性；编码任务有测试就够，最小版先保证"通过"这个数字可信。
- 防作弊：判分前把 `tests` 里的文件原样写回再跑判分命令。agent 看得到测试，改了没用。
- 判分在 agent 用的同一个 sandbox 里跑，agent 写的代码不在宿主上执行。
- 状态四种：`pass / fail / timeout / error`。超时不再跑 check；`error`（Docker 没起来、setup 失败、check 抛错）单独计数并警告，但仍算在成功率分母里，不悄悄排除。
- eval 不 import runtime，只认 `AgentRunner`，组装在 `examples/eval.ts`。

## 代价
判不了没有测试可写的任务（总结、解释、调研）。只保护列在 `tests` 里的文件；agent 把被测函数改成硬编码答案拦不住，靠用例多几个来挡。

## 何时要改
加开放式任务，或需要 agent 看不到的隐藏用例时。

## 如何验证（eval / 测试）
- 有测试证明：把 `test.js` 改成什么都不测，仍然不通过。
- 5 道内置题每道都自检过，但**没有用真实模型跑过**，难度未知；设计页要 20 道，没有对照组。
