# ADR-004 用每包 src/ 行数预算量化"可读"
- 状态：已接受（2026-11-12 回填，2026-11-12 经用户阅读确认）
- 包：全仓
- 来源标记：`DECIDE: 用代码行数上限量化？（候选：每包 ≤ 800 行 / ≤ 1500 行）`（docs/00-goal.md:26）

## 问题
成功标准要求"每个包 README ≤ 一下午读完"。怎么让它可检查？

## 候选
1. 全仓统一上限（800 或 1500 行）。
2. 每个包一个预算，由 `scripts/budget.mjs` 检查，只算 `src/`，不含测试。

## 各家怎么做（附出处）
没有核实过。

## 决定
选 2。`npm run budget` 输出每包 `当前/预算`，超了退出 1。当前预算（行）：core 1000、ai 900、tools 1600、store 500、policy 400、sandbox 600、context 700、skills 400、memory 700、runtime 1200、gateway 800、telemetry 400、eval 900、cli 1400。
规则（AGENTS.md）：超了就删代码，不要调预算。

**已有一次例外**：`@hue/cli` 预算从 400 提到 1400（cli DECISIONS 第 6 条），理由是 TUI 布局和命令都放在配方包里。tools 的 1600 也高于设计页里的 1500 候选值。这两处和"不要调预算"有张力，请你确认接受。

## 代价
行数不等于可读性；只算 `src/`，测试和 README 不计。预算是上限，不是目标。cli 例外说明这个规则在 UI 类包上会失效。

## 如何验证（eval / 测试）
- `npm run budget`。
- "一下午读完"本身没有被验证过（没有人按这个标准读过）。
