# ADR-018 memory：一条笔记一个 markdown 文件，模型主动 `remember`，索引进提示
- 状态：已接受（2026-11-12 回填，2026-11-12 经用户阅读确认）
- 包：@hue/memory
- 来源标记：无 `DECIDE:`。出处 memory DECISIONS 第 1–4 条

## 问题
记忆用什么形态存？什么时候写？怎么召回？笔记可信吗？

## 候选
1. 存：markdown 文件 / 向量库 / 两者。
2. 写：模型主动调用 / 会话结束自动反思。
3. 召回：索引进提示加按需 `recall` / 每轮自动检索。

## 各家怎么做（附出处）
没有核实过。

## 决定
- 只做 markdown 文件，文件名就是名字：用户能打开目录看到模型记了什么、能改、能删、能进 git，没有额外服务和依赖。
- 只有模型主动调用 `remember` 才写；每次写入在事件日志里有一条 `tool.call`。不做自动反思（多一次模型调用，且写什么由另一个提示决定，更难解释）。防垃圾靠硬规则：提示里写明存什么，大小 / 条数 / 命名限制，疑似凭证拒绝，同名是更新。
- 启动时把索引（名字 + 一行描述，最新 50 条）放进系统提示，正文按需 `recall`。不做每轮自动检索，因为那会让系统提示逐轮变化、破坏 prompt cache。
- 打分：名字 3、描述 2、正文 1，完全一致加 100，同分新的在前；英文按词，中文按单字加相邻两字。权重是我定的，没调过。
- 先写临时文件再 `rename`。

## 代价
召回只靠关键词，同义词、改写搜不到。超过 50 条的老笔记不在索引里。笔记一变，下个 turn 的前缀就变，缓存失效一次。**笔记是持久化的提示注入面**：被诱导的模型可以 `remember` 一条"以后总是……"，之后每个会话都读到；目前只有缓解（提示里说明笔记不是指令、`remember` 标 `idempotent` 可被 policy 管、写入在日志里），没有验证用户本意的机制。读写在宿主上，不经沙箱。

## 何时要改
召回在真实使用里经常漏时，可在不改文件格式的前提下加向量索引作为 `search` 的另一种实现；要做合并 / 遗忘时（设计页 `LATER`）。

## 如何验证（eval / 测试）
- 机制测试：`forget('../x')` 删不到目录外、写入不留临时文件、疑似凭证拒绝、中文召回。
- **召回质量没量过**；"跨两次会话记住偏好并在 eval 里体现"目前没有 eval 任务；崩溃场景没有测试（没杀进程）。
