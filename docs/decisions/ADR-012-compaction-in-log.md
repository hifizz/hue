# ADR-012 压缩结果写回事件日志（`context.compacted`）
- 状态：已接受（2026-11-12 回填，2026-11-12 经用户阅读确认）
- 包：@hue/context
- 来源标记：`DECIDE: 压缩结果写回日志（context.compacted 事件）还是只在内存`（docs/packages/context.md:21）

## 问题
压缩（尤其是摘要）的结果，是进日志，还是只存在内存里、每次重算？

## 候选
1. 写回，用 core 已有的 `context.compacted` 事件，里面存替换进去的完整消息。
2. 只在内存，需要时重新压缩。

## 各家怎么做（附出处）
没有核实过。

## 决定
选 1。`Compaction.replacement` 存的是完整消息，所以**回放不需要再调一次模型**，摘要也不会因为重放而变。transcript 从不删，压缩只影响"发给模型的视图"。

配套决定（context DECISIONS 第 0、1 条）：
- 触发：每步调模型前，估算超过预算（默认模型窗口的 80%）就压，压到预算的 50%，避免每步都改写前缀、让 prompt cache 失效；收到 `context_overflow` 则无条件压，目标 `min(目标, 估算 × 0.6)`。
- 切点：user 消息之前，或紧跟 tool 消息之后的 assistant 之前；这样长任务（整个过程只有一条用户消息）也能压，且不会拆开 tool-call 和 tool-result。切在一轮中间时，任务原文要带过去。
- `keepSteps`（默认 6）是下限，不是上限。

## 代价
摘要全文进了日志，日志变大；多次压缩每次都存一份完整的 replacement。

## 如何验证（eval / 测试）
- 集成测试：压缩事件落进日志后，`fold(日志)` 与 turn 结束时的 state 相等。
- 对所有预算和参数组合检查切点结构的测试。
- **没有数据证明摘要质量**，80% / 50% / 6 步都是经验值，没用真实长任务调过。验收里"三种策略在 eval 上有对比数据"要等 `@hue/eval` 跑真实模型。
