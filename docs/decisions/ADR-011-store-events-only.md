# ADR-011 store 只存原始事件，不存派生快照
- 状态：已接受（2026-11-12 回填，2026-11-12 经用户阅读确认）
- 包：@hue/store
- 来源标记：`DECIDE: 存原始事件还是存派生的 Message 快照，或两者`（docs/packages/store.md:18）。同页 `DECIDE: 分支（fork 会话）求职版要不要`（store.md:19）见文末

## 问题
大会话启动时是从事件 `fold` 回来，还是另存一份消息快照？

## 候选
1. 只存事件，启动时 `fold(read())`。
2. 另存消息快照，从快照加之后的事件恢复。

## 各家怎么做（附出处）
没有核实过。

## 决定
选 1。事件是唯一事实源（ADR-001）：快照丢了可以重算，事件丢了回不来。实测 10 万条事件顺序读取约 0.17 秒（见 store README），到这个量级之前不需要快照。

## 代价
会话很大时每次启动都要从头 fold，CPU 和读盘随长度线性增长。

## 何时要改
fold 10 万条以上的会话启动明显变慢时。快照必须可由 fold 重算并校验（存 `seq` + 内容哈希），校验不过就丢弃重算，不能成为第二个事实源。

## 如何验证（eval / 测试）
- `kill -9` 测试；两个连接写同一会话的测试；memory 与 sqlite 共用一份校验逻辑，同一套合同测试都要过。
- 读取速度来自 store README 的基准，本次未重跑。

## 同页的 fork 标记
会话分叉只设计、不实现（`LATER`）：新会话 = 复制源会话到某个 seq 为止的事件，`seq` 重新编号，第一个事件是带 `parent` 的 `session.created`。不写 ADR，设计和不做的理由已在 store DECISIONS 第 3 条。
