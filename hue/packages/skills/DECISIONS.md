# @hue/skills 决定记录

## 1. 加载方式：专门的工具，还是让模型直接 read 文件？

- **选了**：专门的 `load_skill` 工具。
- **为什么**：技能目录在宿主上，而 agent 的 `read` / `bash` 在沙箱里（Docker 只挂载了仓库）。模型看不到技能目录的路径，就没法 `read`。工具由宿主进程执行，不依赖沙箱里有什么。顺带，工具名是个明确的信号，回放里一眼看得出哪次用了技能。
- **代价**：多一个工具说明占 token（只有存在技能时才加）；技能目录的访问规则得自己守（见第 3 条）。Claude Code 是让模型直接读文件还是用专门工具，没对照过源码，`TODO(verify)`。
- **何时要改**：如果沙箱总是能看到技能目录（local 模式、或者把目录挂进容器），直接 `read` 更简单。

## 2. 兼容 Anthropic Agent Skills 格式？

- **选了**：兼容目录布局和 frontmatter 的 `name` / `description`；其余字段忽略。名字规则（小写字母、数字、连字符，≤ 64，和目录名一致）从严执行，不合法的跳过并记入 problems，不让一个坏技能拖垮整个索引。
- **代价**：没有拿官方技能实测过；frontmatter 是手写的小解析器，不是 YAML（见 README）。我对规范的细节也没有核实过，`TODO(verify)`。

## 3. 技能里的文件和脚本：谁读、谁执行？

- **选了**：`load_skill` 能读技能目录里的文本文件，但**不执行任何东西**。脚本要用，模型读出来再用 `bash` 在沙箱里跑。
- **为什么**：执行必须经过 policy 和沙箱，技能包不该有绕过它们的后门。
- **读文件的边界**：用真实路径（realpath）比较，必须在技能目录内且前缀后跟路径分隔符。`../`、绝对路径、指向目录外的符号链接、名字前缀相同的兄弟目录（`pdf` 和 `pdf-private`）都有测试。大小上限 100KB，二进制拒绝。
- **代价**：技能带的脚本在沙箱里没有现成文件，模型得先把内容写进去再跑，多两步。
- **注意**：这是宿主上的读文件，沙箱挡不住它；所以它只能读技能目录，且技能目录是用户自己放的。**下载来的第三方技能等于第三方给模型的指令**，目前没有任何审核或签名。

## 4. 什么时候扫描

- **选了**：每个 turn 开始时扫（`instructions` 和 `tools` 各扫一次，turn 内模型看到的是同一份）；`load_skill` 执行时再扫一次拿最新内容。
- **为什么**：加技能不用重启；扫描是读几个小文件，比缓存失效的麻烦便宜。
- **代价**：技能很多（几百个）时每个 turn 读几百个文件。同一个 turn 里中途改了技能目录，索引和 `load_skill` 可能不一致（模型会得到"没有这个技能"的明确错误）。
- **何时要改**：技能多到扫描变慢时，按目录 mtime 缓存。

## 5. 其他

| 决定 | 原因 |
|---|---|
| 没有技能时不加说明、不加工具 | 不白占 token，也不让模型去找不存在的东西。 |
| 多个目录靠前的赢 | 项目里的技能要能盖过用户级的同名技能。同名被盖掉不报 problem（这是正常用法）。 |
| 描述压成一行并截到 200 字符 | 验收要求"索引每个技能一行"。描述写得长是作者的事，索引不为它买单。 |
| 不做技能之间的依赖和版本 | 求职版不需要；模型自己会按正文去加载另一个。 |
