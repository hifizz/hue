# @hue/policy 决定记录

## 1. "记住这次决定"放在哪？

- **选项**：A 策略自己存；B 只提供组合函数 `withGrants(policy, grants)`，grants 的持久化交给 runtime。
- **选了**：B。
- **为什么**：策略要保持纯函数、不做 I/O（合同要求确定性）。grants 是 runtime 的状态，应该写成 `ext` 事件进日志，会话恢复时才能还原。`grants` 可以是数组（按引用读，runtime 往里 push 立刻生效）或返回数组的函数。
- **只升级 ask**：`withGrants` 只把 `ask` 变成 `allow`，永远不覆盖 `deny`。用户点"总是允许"不应该能绕过 `sudo` 这类硬禁止（有测试）。
- **代价**：grants 目前只能按"工具名 + 字段逐字相等"匹配，不能表达"所有 `git` 开头的命令"。
- **何时要改**：真实使用中发现用户总是在点同一类命令时，再加前缀 / 正则授权。

## 2. 规则要不要支持从 JSON 加载？

- **选了**：不支持。规则是 TypeScript 值，`match` 可以是正则或函数。
- **为什么**：正则和函数都没法直接序列化。要支持就得发明一套"字符串形式的正则 + 内置谓词"的格式，求职版里没有人需要它。
- **代价**：用户不能用配置文件写规则，只能写代码。
- **何时要改**：做 gateway / 配置文件时。到时加一个 `fromJSON`，正则用 `{ regex, flags }` 表示，函数不支持。

## 3. bash 命令要不要分词？怎么分？

- **选了**：分。按 `; & && | ||` 和换行拆成段（引号里的不拆，续行不拆，注释忽略），**每一段单独过规则**：任何一段 `deny` 整条 `deny`；否则任何一段需要 `ask` 整条 `ask`；全部 `allow` 才 `allow`。
- **看不透的结构**（`$(…)`、反引号、`<(…)`、heredoc、子 shell / 分组、变量开头、写文件的重定向、引号没闭合）标成 *opaque*。opaque 的段上，**要看命令内容才放行的 allow 规则降级成 ask**；deny 规则照常生效。不看命令内容的规则（比如 `yolo` 的全放行）是用户明确的选择，不降级。
- **为什么**：任务书要求防 `git status; rm -rf /` 这类绕过。不做完整的 shell 解析器：那是个无底洞，而且做了也只是"更难绕过"，不是安全。
- **这不是安全边界**，真正的边界是 sandbox。已知能绕过或者放得过松的地方：
  - `presets.coding()` 放行 `cat <任何文件>`，在 `local` 沙箱里能读到 `~/.ssh` 之类。容器里看不到宿主文件，所以问题不大；用 `local` 时要自己加规则。
  - 放行了 `git diff` 等，但 `git diff --output=<文件>` 会写文件。放行了 `npm test`，而它会执行 `package.json` 里任意脚本。放行 `node <脚本>` 因为跑项目自己的代码正是编码 agent 的工作。
  - 别名、函数、`eval`、`bash -c '…'`（会被当成 `bash` 命令本身，不在白名单里，所以会 ask，但规则写得宽松的话不一定）。
  - 分词器和真实 shell 的差异：`${…}` 展开、算术展开、`case` 语句里的 `;;` 等都没有专门处理。
- **代价**：复杂但无害的命令（带 `$(…)` 的）会多问一次。宁可多问。
- **何时要改**：真实使用中发现误问太多，或有人构造出绕过时。到时优先补测试，再改分词。

## 4. `presets.coding()` 的放行 / 拒绝清单怎么定

- **放行**：`effects: none` 的工具（read / list / glob / grep）、`edit`、`write`、以及一份"看一眼和跑项目自己的测试构建"的 bash 命令白名单（git 只读命令、ls / cat / head / tail / wc / grep / rg、`node <脚本>`、`npm test` 和 `npm run test|build|lint|check|typecheck`、tsc、pytest、cargo / go 的 test / build）。
- **拒绝**（带给模型看的原因）：`sudo / su / doas`、对 `/`、`~`、`$HOME`、`..`、`*` 的 `rm`、`git push --force`、`mkfs` 和 `dd`。
- **其他一律 ask**，包括 `rm -rf node_modules`、`curl`、`npm install`。
- **为什么 edit / write 直接放行**：它们走 sandbox 的文件接口，路径越界已经被拦住；而且逐次确认改文件会让 agent 没法用。在 `local` 里它们能改仓库里的任何文件，这是编码 agent 的本职。
- **这份清单是猜的**，没有用真实任务调过。
- **extra 参数**：调用方的规则排在内置规则**前面**，可以加项目特有的放行（`make`）或禁止。

## 5. 其他

| 决定 | 原因 |
|---|---|
| `deny` 没写 `reason` 时自动生成，带规则编号 | 合同要求 deny 必须说明原因（模型会读）。 |
| `ask` 的提示是 `Allow <工具>? <摘要>`，bash 显示命令本身、其他显示参数 JSON，超过 300 字符截断并标出原长度 | 给人看的，要能一眼看清在批准什么。 |
| 带 `g` / `y` 标志的正则每次匹配前重置 `lastIndex` | 否则同样的输入第二次可能得到不同结果，违反确定性（有测试）。 |
| 决定里不放值为 `undefined` 的字段 | 决定会进事件日志，经 JSON 往返后 `undefined` 键会消失，前后不相等。测试里发现了一次这样的问题。 |
| 工具名通配只有 `*` | 够用；其他字符按字面，不会被当正则。 |
