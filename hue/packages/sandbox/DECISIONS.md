# @hue/sandbox 决定记录

## 1. local 的环境变量白名单

- **选了**：只给 `PATH`、`HOME`、`LANG`，再加构造时的 `env` 和每次 exec 传入的 `env`。
- **为什么**：模型执行的命令不该读到宿主的 `ANTHROPIC_API_KEY` / `AI_GATEWAY_API_KEY`。有测试：宿主设了变量，命令里 `printf $VAR` 是空的。
- **代价**：依赖别的环境变量的命令（`JAVA_HOME`、代理设置、`NODE_OPTIONS`）会失败，要显式传。
- **何时要改**：真实仓库需要更多变量时，按需加到构造选项里，而不是放宽白名单。

## 2. docker 默认网络：`bridge`（联网），不是任务书写的 `none`

- **选项**：A `none`（任务书默认）；B `bridge`（联网）。
- **选了**：B，`network: 'none'` 可以一行关掉（有测试：只剩 `lo`）。
- **为什么**：这是你的明确决定——本地测试优先，先放开。`npm install`、拉依赖、请求本地服务都要网络，`none` 会让大多数真实仓库跑不起来。
- **代价**：命令能向外发数据。能被发出去的只有挂载目录里的内容：API key 不在容器环境里（模型调用在宿主上），宿主上别的目录看不到（有测试）。但仓库副本里的代码和 `.env` 之类的文件是可以被带出去的。
- **何时要改**：处理不信任的仓库，或仓库里有密钥时，用 `network: 'none'` 并把依赖预装进镜像。

## 3. docker 用 CLI，不用 Engine API

- **选了**：CLI（`docker run -d` 起一个 `sleep` 容器，`docker exec` 跑命令）。
- **为什么**：零依赖，够用，任务书也这么建议。
- **代价**：每次 exec 多一个 `docker` 进程（本机约 0.1 到 0.3 秒）；错误只能从 stderr 文本里读。
- **何时要改**：exec 频率高到延迟成为问题，或要流式读容器日志时。

## 4. 文件接口走挂载目录，只有 exec 进容器

- **为什么**：docker 只挂载一个目录，读写文件直接在宿主上做，路径检查（含符号链接）和 local 共用一份代码（`fs.ts`），省掉每次 `docker exec cat`。
- **代价**：宿主上的符号链接解析和容器里不同。一个指向容器内某路径（如 `/etc/passwd`）的链接，在宿主上会被解析成宿主的 `/etc/passwd`，因此被拒绝。偏保守，不会放过，但可能误拒。
- **局限**：检查和使用之间有时间差（TOCTOU）。威胁模型是"模型写错路径"，不是对抗性的并发进程。

## 5. 杀进程：docker 里按环境变量标记找进程，local 用进程组

- **docker**：不能只杀 `docker exec` 这个客户端，容器里的命令不会因此退出。每次 exec 带一个唯一的 `HUE_EXEC_ID` 环境变量，超时或取消时在容器里扫 `/proc/*/environ` 找到带这个标记的进程并 `kill -9`（扫两遍，应对杀的过程中又 fork 的）。不用进程组，是因为后台命令（`cmd &`）可能换过组；环境变量会被子孙继承。再 `SIGKILL` 客户端兜底，保证 exec 一定返回。
- **local**：`detached` 让子进程自成进程组，`kill(-pid)` 杀整组。
- **为什么要杀整棵**：只杀 shell 时，存活的后台进程还握着 stdout 管道，`close` 事件要等它们结束，exec 就一直不返回。有测试：`sleep 20 &` 加 400ms 超时，要求 6 秒内返回，且事后 `kill -0` 确认后台进程已死（超时和取消各一个）。
- **假设**：容器里有 `tr`、`grep -x`、`/proc`。在 alpine（busybox）和 node:22 上都测过。
- **局限**：用 `setsid` 之类主动脱离、又清掉环境变量的进程杀不到。容器本身会在 dispose 或 TTL 到期时整个删掉，所以最终不会留下。

## 6. 输出上限与截断标记

- 每个流最多收集 1,000,000 字节，超过的继续读掉但不保存（不读的话子进程会因管道写满而卡住），文本末尾加 `[output truncated at 1000000 bytes]`。core 的 `ExecResult` 没有"被截断"字段，所以用文本标记；给模型看的长度仍由工具截断（`@hue/tools` 的 30 KB）。
- 按字节收集、最后一起解码，被切在包边界的中文不会变成 `�`（有测试）。

## 7. docker 容器的生命周期

- 第一次 exec 才启动，之后复用，`dispose()` 删除，可重复调用，之后不能再用。启动失败不会被缓存成永久失败。
- 容器带 `--rm --init`（`--init` 回收被杀掉的子进程，不留僵尸）和 `sleep <TTL>`（默认 4 小时）：agent 进程崩溃来不及 `dispose` 时，容器自己会退出，不会永远留着。带 label `hue.sandbox=1`，方便手动清理：`docker ps -a --filter label=hue.sandbox=1`。
- 以宿主的 uid:gid 运行（不是 root），否则写进挂载目录的文件归 root，宿主上删不掉。`HOME=/tmp`。
- 默认限制：2 GB 内存、2 个 CPU、1024 个进程。

## 8. 没做

- **远程沙箱（E2B、Fly Sprites）**：接入草图是实现同一个 `SandboxPort`——`exec` 走它们的 API，文件接口走它们的文件 API，路径检查在它们那边做。没有实现。
- **macOS 之外的验证**：只在 macOS + OrbStack 上跑过。Linux 原生 Docker 上的 bind mount 权限、cgroup v1 没验证。
